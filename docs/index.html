Homelab monitoring — Nginx reverse proxy

Extension of homelab-monitoring: Uptime Kuma stays on the Compose network; Nginx is the only published front door.

Architecture

Browser / LAN client
        |
        |  :8080 (HTTP)
        v
   +---------+     basic auth + rate limit + headers
   |  Nginx  |----------------------------------------
   +----+----+
        |  /health  -> 200 ok (Nginx itself)
        |  /        -> proxy_pass
        v
   +-------------+
   | Uptime Kuma |
   |   :3001     |  (expose only, no host port)
   +-------------+

Uptime Kuma no longer publishes port 3001 on the host. Clients talk to Nginx on NGINX_HTTP_PORT (default 8080). WebSocket upgrade headers stay in place so the dashboard live updates work.

Routes

PathAuthRate limitResponse
/health none none 200 plain ok from Nginx
/ (and subpaths) HTTP basic 2 req/s, burst 4 Proxied to uptime-kuma:3001

Security choices

  • Basic auth on the dashboard with a demo user (monitor / changeme) in nginx/htpasswd. Change it before any network wider than a lab LAN.
  • Rate limiting returns 429 when a client exceeds the budget, which slows down password guessing and accidental loops.
  • Security headers on proxied responses: X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, and a tight CSP.
  • No host bind for Kuma — the monitoring UI is only reachable through Nginx.
  • Optional TLS — generate a self-signed cert with scripts/generate-nginx-tls.sh and enable nginx/conf.d/ssl.conf.example for local HTTPS.
  • gzip for text responses; server_tokens off.

Run locally

Localhost URLs below are only for a machine that runs Docker Compose.

git clone https://github.com/ottonielmorais2008-rgb/homelab-monitoring.git
cd homelab-monitoring
cp .env.example .env
docker compose up -d

# Health (no password)
curl -s http://localhost:8080/health

# Dashboard (demo credentials)
open http://localhost:8080
# user: monitor   password: changeme

Full Uptime Kuma and Telegram setup stays in the repository README.

CI coverage

GitHub Actions validates both Compose files, lints YAML and Markdown, runs nginx -t in the official Nginx image, then brings up docker-compose.ci.yml (tiny upstream stand-in) and checks:

  • /health → 200
  • / without credentials → 401
  • / with demo credentials → 200 + security headers
  • burst traffic → at least one 429

What went wrong

  • Published Kuma port vs front door. The original stack published 3001 with no auth until the first admin account existed. Putting Nginx in front without removing that host port would leave an unauthenticated bypass. The Compose file now only exposes Kuma on the internal network.
  • WebSockets. The Uptime Kuma UI needs Upgrade / Connection headers. A plain proxy_pass without them looked “up” on /health while the dashboard stayed blank.
  • CI and the real image. Pulling louislam/uptime-kuma:2 on every PR is slow and the healthcheck allows a long cold start. CI uses docker-compose.ci.yml with a tiny Nginx upstream on port 3001 so route and security checks stay fast.
  • htpasswd comments. Nginx treats every line in the password file as a user entry. Comments belong in nginx/README.md, not in htpasswd.
  • Local Docker on the agent box. The build agent has no Docker daemon. Config is checked with nginx -t inside a container on GitHub-hosted runners; do not expect docker compose up on that box.
